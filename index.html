05 / Engineering decisions

What makes the
architecture interesting.

These are the points to discuss in a technical interview. The website explains not only what exists, but why the boundaries matter.

A

O(1) blob access

Compact volume indexes and volume-level mapping keep lookup work small while avoiding a giant per-object control-plane index.

B

Direct data path

Clients can cache mappings and reach volume servers directly, reducing unnecessary control-plane work during reads.

C

Durability choices

Replication favors straightforward redundancy and performance; erasure coding improves capacity efficiency for suitable workloads.

D

Cloud native

Docker and Kubernetes deployment paths make the system operable as a real cluster rather than only a local development process.

Guided product walkthrough

SovereignFS in 60 seconds

01 · Upload

Your application enters through S3 or a filesystem interface. The metadata/control layers determine where the object belongs.

02 · Store

Volume servers hold the actual blob data. Replication or erasure coding can provide durability depending on policy.

03 · Read

After placement information is known, the client can take the direct data path to the relevant volume server.

04 · Fail

If a storage node disappears, the system can use healthy replicas or repair mechanisms rather than treating one node as the whole system.

05 · Scale

Add volume servers for more storage capacity. The access model stays the same while the cluster expands.
